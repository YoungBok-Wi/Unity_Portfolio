# Kitchen Riot

## 포트폴리오 개요

AI 에이전트 오케스트레이션으로 기획부터 QA까지 진행한 소규모 게임 개발 시연 샘플 프로젝트.
AI는 Claude Fable 5.1 -> 요금제 종료 이슈로 GPT-5.6 Sol을 사용했다.

프롬프트 한 번으로 시작해 개선 루프 4회를 돌린 결과물이며, 그 과정의 업무지시서·레포트·컨셉 문서·리소스 생성 기록을 함께 담았다.
미사용 모듈·리소스 원본·용량이 큰 기록 등 불필요한 것들은 대부분 이 저장소에서 제외했다. (`.gitignore`의 `_Data` 항목)

`Assets/_Library` 내용은 대부분 과거에 직접 작성한 코드 중 확장성 좋은 것들을 재사용한 것이다.

## 게임 개요

요리사가 반란 식재료를 처치하며 랜덤 방을 돌파하는 2D 사이드뷰 캐주얼 로그라이트.

- 환경: Unity 6000.4 · URP 17 · Input System 1.19, Windows 1920x1080
- 씬: `Scene_Lobby`(캐릭터 선택·설정) · `Scene_Game`(방 진행·전투)
- 조작: 이동 `A`/`D`, 점프 `Space`, 공격 `J`, 일시정지 `Esc`
- 캐릭터 2종
  - 식칼: 근접 3단 콤보, 기본 사용
  - 케첩 건: 원거리 연사, 5번째 방 클리어 시 영구 해금
- 방 진행
  - 클리어 후 2택 선택지 — `[전투/회복]` `[회복/능력]` `[전투/보스]` `[전투/전투]` 중 랜덤
  - 선택 카드에 다음 방 적 구성 미리보기, HUD에 지나온 방 이력
  - 능력방 3택1(6종), Crumb 재화로 리롤
- 적·보스 (FSM)
  - 일반 3종: 근접 Apple · 탱커 Watermelon · 원거리 Banana
  - 보스 2종: Pumpkin(근접 돌진) · Pineapple(원거리 가시) — Idle/Move/Skill1/Skill2/Enrage, 발밑 전조
- 저장: 해금·최고 기록·설정 (PlayerPrefs)

## AI 활용

### 커스텀 스킬 & 오케스트레이션

작업 단위마다 입력·절차·완료조건을 적은 커스텀 스킬 시스템을 제작해 사용 중이다.
다양한 AI 하네스 환경에서 작동할 수 있도록 하고 모든 프로젝트에 공통으로 적용된다.
작은 단위의 스킬로 지시 준수율을 높이기 위한 목적도 있다.

진행 순서는 아래와 같다.

1. 업무 지시 — 사용자가 자유 형식으로 요구를 적는다
2. Job 생성 — 오케스트레이터가 업무 맥락을 `job.md`에 정리한다
3. 업무 분해 — 요구를 영역별 체크리스트 항목으로 나눈다
4. 스킬 탐색 — 항목마다 담당 스킬을 고르고, 같이 해야 할 앞뒤 스킬을 체인으로 묶는다
5. Work 편성 — 유사 작업을 Work로 묶고 `order.md`에 스킬별 업무지시를 쓴다
6. 수행 — 서브에이전트(워커)를 만들어 순차 또는 병렬로 Work를 넘긴다. 워커는 실측값을 근거로 `result.md`를 쓰고, 절차가 막히면 우회하지 않고 보고한다
7. 커밋 — 오케스트레이터가 레포트로 체크리스트를 갱신하고 커밋한다. 예외가 있으면 보완 Work를 바로 다음에 끼운다

워커는 커스텀 스킬 문서의 절차대로 작업하고 결과를 레포트로 남긴다. 기록은 [`_Data/Job/`](_Data/Job/)에 있다.

### 리소스 자동화

이미지 생성과 가공은 자동화 워커가 한다 ([`_Data/AutomationWorker/`](_Data/AutomationWorker/)).
자동화마다 `Input/options.json` → `Output/` 규약이 있고, 워커가 큐를 받아 순서대로 돈다.

- 생성 (`Generate/codex_image`) — 프롬프트로 컨셉아트·일러스트·아이콘·애니메이션 시트를 만든다
- 가공 (`Process/image_normalize`) — 리소스를 등록하면 자동으로 걸려 규격대로 배경 제거·리사이즈·정렬해 리소스 경로에 복사한다

### 타입 & 테이블 & 코드 구성

AI가 생성한 컬럼 타입 정의와 테이블 시트(xlsx)를 익스포트하면 `Assets/_Library/_Core/GenerateScript/`의 C#과 `Resources/Table/`의 JSON이 생성된다.

### 컨셉 & 씬 구성

[`_Data/Concept/`](_Data/Concept/)의 컨셉 문서 4종(게임·밸런스·리소스·씬)이 정본이고, 코드·데이터·씬은 여기서 파생된다.
씬 셋업 시 `씬컨셉`의 사용 모듈·UI 목록을 읽어 AI가 MCP를 활용해 매니저·팝업·오브젝트 등을 씬에 추가한다.

### 이번 포트폴리오의 프롬프트 구조

- 게임 요구를 한 문단으로 — 씬 2개, 사이드뷰 캐주얼, 검·총 캐릭터와 5번째 방 해금, 4종 랜덤 선택지, 적 3종·보스 2종 FSM
- 그 외 요소는 알아서 채우고 자율 진행
- 완성 후 계속 개선 루프, 개선 회차마다 Job 1개
- 기존 모듈(`inAsset=false`) 재활용

프롬프트 원문은 [`Job_001/job.md`](_Data/Job/Job_001/job.md)에 있다.
해당 프롬프트에 따라 `Job_001`(1차 완성)과 `Job_002`(개선 1회차)가 돌았고, 개선 1회차 뒤 중지했다가 "한 번만 더" 지시로 `Job_003`(개선 2회차)을, 메인 에이전트가 직접 상황을 확인해 편성하는 방식으로 `Job_004`(개선 3회차)를 돌렸다. `Job_005`(개선 4회차)는 아래 폴리싱 작업에서 `직접` 모드로 진행했다.

## 폴리싱 작업

폴리싱은 인간이 완성된 게임을 직접 플레이하고 문제를 구체적인 오더로 정리한 뒤, AI가 기존 오케스트레이션 절차로 반영하는 단계다.

### 7회차

- 전 팝업의 화면 스케일 기준을 통일하고 프레임형 팝업의 페이드·회전 등장 연출을 보강했다.
- 방 선택 규칙, 5방 주기 보스전, 웨이브 변형, 넉백 곡선·경직과 공격 판정 타이밍을 조정했다.
- 플레이어 FSM과 씬 상주 구조를 추가하고 `PlayerCharacter`·`Room`·`RoomSelect`·`Game`·`Enemy`·`Boss`·`Unit`·`Data` 모듈로 역할을 재편했다.
- 적 방향·타격 이펙트·저체력 비네트·얼굴 타일 씬 전환을 보강하고 SpriteAnim을 `Resources` 로드에서 Inspector 참조 방식으로 전환했다.
- 구 매니저와 삭제된 Odin Inspector 의존을 제거한 뒤 두 씬의 매니저·플레이어 참조와 프리팹 무결성을 다시 검증했다.

### 8회차

- 얼굴 타일 리소스를 투명 배경에 맞게 다시 생성하고 실제 이미지 크기·점유율과 에셋 설정을 정리했다.
- 삭제된 Odin Inspector 의존과 씬 셋업 결손을 보완하고 플레이어 상주·매니저 참조를 복구했다.

### 9회차

- 넉백을 FSM 상태로 분리하고 이동 커브와 종료 후 스턴 시간을 `LocalGameManager`에서 조정할 수 있게 했다.
- Face 씬 전환의 84개 타일에 플레이어 얼굴을 넣고 대각선 순서로 튀어나왔다 사라지는 연출을 적용했다.

## GPT6 Astra 이후의 AI 방향성

GPT6 Astra는 이전 세대의 발전 속도와 비교해 프롬프트 준수율이 눈에 띄게 좋아졌다. 하네스를 통해 개인과 팀의 구조를 AI에게 강제하는 방식은 더 유용해질 수 있다.

반대로 모델의 자율 판단 능력이 커질수록 하네스가 AI의 능력을 제한할 가능성도 커진다. 규칙은 결과 재현성과 안전에 필요한 경계를 분명히 하되, 모델이 더 나은 방법을 선택할 여지를 막지 않도록 세심하게 설계해야 한다.
