# 업무지시서

## 1. 게임컨셉 작성

**대상 스킬**: 게임개발_구성_컨셉_게임_작성

**"taskContent"**: 2D 사이드뷰 캐주얼 로그라이트 액션 게임의 `게임컨셉` 최초 작성 (장르 하위 `게임개발_구성_컨셉_게임_액션_작성` 포함)

**업무**

- 선행 `게임개발_구성_컨셉_질문`으로 현재 `게임컨셉`·정본 ID 등재 현황을 조회한 뒤 작성한다 (문서는 현재 비어 있다)
- 장르·설정: 2D 사이드뷰 액션 로그라이트, 캐주얼 그래픽. 테마는 기존 리소스(`AnimationSheet_Casual_*`·`Icon_Casual_Weapon/Knife·Gun`·`Illust_Casual_Tile/Kitchen` 등 주방·음식 테마)를 재사용할 수 있게 "주방 요리사 vs 반란 식재료"로 잡는다
- 씬 2개: `Scene_Lobby`(캐릭터 선택·시작·설정·해금 현황), `Scene_Game`(방 진행·전투·결과)
- 플레이어 캐릭터 2종: 검(Knife, 근접 3단 콤보) — 초기 사용 가능, 총(Gun, 원거리 연사) — 5번째 방 클리어 시 영구 해금 (저장 유지)
- 방 진행 루프: 방 클리어 → 다음 방 2택 선택지 팝업 → 선택 → 입장. 선택지 세트는 [전투/회복]·[회복/능력]·[전투/보스]·[전투/전투] 4가지 중 랜덤이며 보스방 클리어 시 런 종료(결과 → 로비). 지나온 방 이력 확인 UI와 다음 방 적 구성 미리보기를 필수 요소로 등재한다
- 방 종류 4종: 전투(적 웨이브 처치), 회복(HP 회복), 능력(강화 3택1), 보스(보스 1종 등장)
- 일반 적 3종: 근접 공격형(Apple)·탱킹형(Watermelon)·원거리형(Banana). 보스 2종: 각각 FSM 상태 3개 이상의 패턴(대기·추격·근접 패턴·원거리 패턴·광폭화 등)으로 정의하고 이름·ID를 정본에 등재한다
- 기타 요소(재화·강화 종류·조작 입력·게임 오버·저장 항목·프로젝트 설정)는 포트폴리오 품질 기준으로 채운다 — 정본 ID(캐릭터·적·보스·방 종류·능력)는 모두 이 문서에서 확정한다
- 완료 기준: 후속 `게임개발_구성_컨셉_게임_검증` 합격

## 2. 밸런스컨셉 작성

**대상 스킬**: 게임개발_구성_컨셉_밸런스_작성

**"taskContent"**: 업무 1이 확정한 정본 ID·게임 루프를 전제로 `밸런스컨셉` 최초 작성과 수치 기준이 실릴 테이블·고정값 골격 등록

**업무**

- 선행 `게임개발_구성_데이터_질문`·`게임개발_모듈_질문`·`게임개발_프리셋_파일_질문`으로 현재 데이터·모듈·프리셋 현황을 조회한다
- 수치 기준: 플레이어 2종 스탯(HP·공격력·이동속도·공격속도·사거리), 적 3종·보스 2종 스탯과 방 순번별 성장 곡선, 방별 적 웨이브 구성, 회복량, 능력 강화 종류·수치, 총 해금 조건(5번째 방 클리어), 런 길이 목표(보스까지 6~10방)
- 후속 `게임개발_구성_데이터_테이블_생성`·`게임개발_구성_데이터_고정값_생성`으로 수치가 실릴 미등록 테이블(캐릭터·적·보스·방·능력·웨이브 등)과 고정값 골격을 등록한다 (필드·값은 Work_2 담당)
- 완료 기준: 후속 `게임개발_구성_컨셉_밸런스_검증` 합격

## 3. 리소스컨셉 작성

**대상 스킬**: 게임개발_구성_컨셉_리소스_작성

**"taskContent"**: 캐주얼 주방 테마의 `리소스컨셉` 최초 작성과 게임 전체 컨셉아트 확보

**업무**

- 선행 `게임개발_구성_리소스_질문`으로 리소스 노드 트리·타입·파일 등록 현황(특히 `inAsset` 127건의 `Casual` 계열)을 조회하고 재사용 대상과 신규 제작 대상을 문서에 구분해 적는다
- 신규 제작 필요 예상: 플레이어 공격(검·총) 애니메이션, 보스 2종 애니메이션시트, 사이드뷰 배경(로비·방 종류별), 방 종류 아이콘, 원거리 적 투사체
- 후속 리소스 파일 체인(`게임개발_구성_리소스_파일_생성` → 구성 → `게임개발_구성_리소스_파일_이미지_제작` → 업로드)으로 `Concept_Resource` 타입의 게임 전체 컨셉아트를 확보한다
- 완료 기준: 후속 `게임개발_구성_컨셉_리소스_검증` 합격

## 4. 씬설정 작성

**대상 스킬**: 게임개발_구성_컨셉_씬_생성

**"taskContent"**: `Scene_Lobby`·`Scene_Game` 두 씬의 `씬설정` 작성·검증·외부 적용과 씬 파일·골격·셋업

**업무**

- 대상: `Scene_Lobby`(문서 비어 있음), `Scene_Game`(기존 내용 있음 — 조회 후 이번 컨셉에 맞게 수정)
- 문서가 이미 존재하면 생성을 건너뛰고 사유를 보고한 뒤 `게임개발_구성_컨셉_씬_작성`으로 내용을 채운다
- "사용 모듈"은 기존 모듈 재사용을 우선한다 — `inAsset=true` 모듈(Popup·Save·Sound·Table·Value·Number·Language·Icon·Deal 등)과 `inAsset=false`인 `FSM`·`CharacterPhysics`·`Bank`·`Delegate`·`ObjectPool`을 후보로 검토하고, 게임 고유 모듈(방 진행·전투·캐릭터 해금 등)은 최소 개수로 신규 등재한다
- UI 목록: 로비(캐릭터 선택·시작·설정·해금 잠금 표시), 게임(HUD HP·방 순번·방 이력, 방 선택 팝업 + 적 미리보기, 능력 선택 팝업, 일시정지, 결과 팝업). 필수 `팝업` 3종 포함·제외와 취소 입력 주체를 확정한다
- Object 목록: 플레이어 2종, 일반 적 3종, 보스 2종, 투사체, 배경·바닥
- 후속 체인을 순서대로 수행한다: `게임개발_구성_컨셉_씬_검증` → `유니티엔진_씬_생성` → `게임개발_모듈_폴더_생성`·`게임개발_모듈_폴더_구성`(신규 모듈 골격 + `inAsset=false` 재사용 모듈 켜기) → `게임개발_구성_리소스_타입_생성`·구성·파일 생성·구성·이미지 제작·업로드(씬별 `Concept_Scene_{씬ID}` 컨셉아트, 타입 없을 때만 생성) → `게임개발_프리셋_파일_생성`(미제작 Object·팝업 더미) → 오브젝트·팝업 삭제(목록에서 빠진 것) → `게임개발_프리셋_파일_팝업_구성` → `유니티엔진_씬_셋업_실행`
- 완료 기준: 두 씬 파일이 빌드에 등록되고 셋업이 통과하며 컴파일 에러 0건
- 비고: 이 Work 전체에서 `confirmed`·`reuse` 값은 변경하지 않는다. 막힘·결함은 우회하지 않고 레포트로 보고한다
