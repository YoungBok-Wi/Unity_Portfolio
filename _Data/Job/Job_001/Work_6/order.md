# 업무지시서

## 1. 플레이테스트 대상 조회

**대상 스킬**: QA_유니티게임개발_플레이테스트_질문

**"taskContent"**: `Scene_Lobby`·`Scene_Game`의 조작 가능 UI·오브젝트 상태와 기존 시나리오·치트 명세 확인

**업무**

- 두 씬의 팝업·오브젝트 MCP 노출 항목을 조회해 시나리오 작성 근거로 정리한다

## 2. 플레이테스트 계획 작성

**대상 스킬**: QA_유니티게임개발_플레이테스트_계획

**"taskContent"**: 사용자 명시 요청("완성 후 계속 루프 돌면서 개선")에 따른 전체 게임 루프 검증 시나리오 작성

**업무**

- 시나리오 필수 항목: 로비 캐릭터 선택(총 잠금 상태 확인) → 게임 시작 → 전투방 클리어 → 방 선택 팝업(2택, 세트 4종 중 하나, 적 미리보기 표시) → 회복방·능력방 동작 → 5번째 방 클리어 시 총 해금 알림·저장 유지(재시작 후 확인) → 보스방 2종 각각 FSM 패턴 전환 확인 → 결과 팝업 → 로비 복귀. 방 이력 UI가 지나온 방을 정확히 표시하는지 포함
- 비정상 입력·회피 플레이·텍스트 표시(잘림·넘침)·캐릭터 대 배경 크기 비율·컨셉아트 유사성 판정 시점을 포함한다
- 치트 명세는 `QA_유니티게임개발_플레이테스트_치트_작성`으로 위임한다 (방 순번 점프·HP 조작·보스 즉시 진입·해금 초기화)
- 산출물은 `_Temp/`에 저장한다

## 3. 플레이테스트 실행

**대상 스킬**: QA_유니티게임개발_플레이테스트_테스트

**"taskContent"**: 업무 2 시나리오대로 플레이 모드 구동·상태 대조·결함 보고

**업무**

- 시나리오 전 단계를 구동하고 기대 결과와 대조한다. 화면 캡처를 단계별로 남긴다
- 결함은 수정하지 않는다 — 재현 절차·실측값·담당 영역(모듈/프리셋/데이터/리소스)을 레포트에 지목한다. 이 레포트가 다음 개선 루프 편성의 입력이다
- 완료 기준: 시나리오 전 단계 판정 완료(합격·불합격 명시), 에러 로그 수집. 막힘은 우회하지 않고 보고한다
