# 업무지시서

## 1. 표준 버튼 구조와 적용 대상 조회

**대상 스킬**: 게임개발_프리셋_파일_질문

**"question"**: 라이브러리 표준 `Control_Button` 구조와 `Animator_Button`을 사용하는 게임 컨트롤·팝업 버튼의 구조 및 사용처를 전수 확인한다.

**업무**

- `Control_Button` 계열의 계층·컴포넌트·Animator·표시 슬롯 구조를 확인한다.
- 게임 `컨트롤`과 `팝업`에서 표준 구조가 아닌 버튼을 모두 식별한다.
- 기존 클릭 배선·직렬화 참조·표시 리소스·레이아웃의 보존 대상을 확인한다.

## 2. 게임 컨트롤 버튼 구조 통일

**대상 스킬**: 게임개발_프리셋_파일_컨트롤_구성

**"content"**: 조회에서 확인한 게임 컨트롤의 비표준 버튼을 용도에 맞는 표준 `Control_Button` 구조로 교체한다.

**업무**

- `Control_AbilityCard`, `Control_GameFrame`, `Control_RoomChoice`와 조회에서 추가 확인된 대상을 수정한다.
- 기존 버튼 크기·앵커·표시·클릭 배선과 `Animator_Button` 동작을 보존한다.
- 변경 뒤 각 버튼이 표준 계층·컴포넌트 구조를 갖는지 재조회한다.

## 3. 게임 팝업 버튼 구조 통일

**대상 스킬**: 게임개발_프리셋_파일_팝업_구성

**"content"**: 조회에서 확인한 게임 팝업의 비표준 버튼을 용도에 맞는 표준 `Control_Button` 구조로 교체한다.

**업무**

- `Popup_Ability`, `Popup_HUD`, `Popup_Lobby`, `Popup_Pause`, `Popup_Result`, `Popup_Setting`과 조회에서 추가 확인된 대상을 수정한다.
- 기존 버튼 크기·앵커·표시·클릭 배선과 `Animator_Button` 동작을 보존한다.
- 변경 뒤 각 버튼이 표준 계층·컴포넌트 구조를 갖는지 재조회한다.

## 4. 변경 프리셋 개별 익스포트

**대상 스킬**: 게임개발_프리셋_파일_익스포트

**"presetId"**: 변경된 `컨트롤`·`팝업` 프리셋 ID를 문자열로 하나씩 전달한다.

**업무**

- 변경된 프리셋 원본을 각각 개별 익스포트하고 재임포트한다.
- `confirmed`·`reuse`는 변경하지 않는다.
- 코드 작성·컴파일 체인은 스크립트 계약을 바꾸지 않는 구조 교체이므로 제외한다.
- 프리셋 생성·노드 구성·컨셉·모듈·리소스·애드온·오브젝트·씬 셋업 체인은 기존 표준 프리셋 재사용 범위이므로 제외한다.
- `유니티엔진_씬_검증` 스킬은 사용자 지시에 따라 실행하지 않는다.
- 완료 근거는 `c01`·`c02`에 대응한다.
