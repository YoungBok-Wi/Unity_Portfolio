# 업무지시서

## 1. 넉백·타격 모듈 현황 조회

**대상 스킬**: 게임개발_모듈_질문

**"taskContent"**: `Unit`·`Game` 모듈의 넉백 상태, 애니메이션 재생, 타격 이펙트 호출 경로 조회

**업무**

- 예외 스택의 호출부와 공용 API를 모두 확인해 `Hit` 클립 강제 재생 지점과 이펙트 중단 원인을 확정한다.
- 기존 헬퍼·선택 재생 패턴과 모듈 원본·사본 방향을 확인한다.

## 2. 넉백 애니메이션 계약 조회

**대상 스킬**: 게임개발_구성_컨셉_질문

**"taskContent"**: 넉백 FSM의 애니메이션·타격 이펙트 정본 계약 조회

**업무**

- 넉백 상태가 반드시 `Hit` 클립을 요구하는지와 타격 이펙트의 책임 위치를 정본에서 확인한다.

## 3. 유닛 프리셋 애니메이션 구성 조회

**대상 스킬**: 게임개발_프리셋_파일_질문

**"taskContent"**: 넉백 가능한 플레이어 2종·일반 적 3종의 `SpriteAnimPlayer` 클립 구성 조회

**업무**

- 각 프리셋의 `Hit` 클립 보유 여부와 넉백 상태 배선을 대조한다.
- 공용 상태가 프리셋별 선택 클립 차이를 안전하게 처리할 기준을 확보한다.

## 4. 넉백 예외 원인 수정

**대상 스킬**: 게임개발_모듈_폴더_작성

**"taskContent"**: `Unit` 중심의 공용 원인 최소 수정과 타격 이펙트 흐름 복구

**업무**

- `Hit` 클립이 없는 넉백 가능 유닛에서도 상태 진입이 예외 없이 계속되도록 기존 코드 패턴을 재사용한다.
- 예외 제거로 `LocalGameManager.Hit`의 후속 타격 이펙트 호출이 정상 진행되게 한다.
- 신규 추상화·의존성·프리팹 클립 복제는 만들지 않는다.

## 5. 변경 모듈 익스포트

**대상 스킬**: 게임개발_모듈_폴더_익스포트

**"moduleIds"**: 실제 수정된 `Unit`·`Game` 모듈

**업무**

- 수정된 원본만 엔진 사본과 동기화하고 export 결과를 확인한다.

## 6. Unity 컴파일 확인

**대상 스킬**: 유니티엔진_컴파일_실행

**"scope"**: 넉백 예외 수정 반영 후 전체 스크립트 컴파일

**업무**

- 재컴파일 완료와 컴파일 오류 `0건`을 확인한다.
- 모듈 노드·폴더 생성·메타 구성과 데이터·리소스 질문은 기존 대상·계약을 바꾸지 않으므로 제외한다.
